# Global Claude Settings

---

## 🔑 환경변수 및 보안

민감정보는 항상 `~/.claude/.env`에서만 관리한다:
- `GITHUB_TOKEN`: GitHub MCP 및 gh CLI 인증
- `NOTION_TOKEN`: Notion MCP 인증

보안 규칙:
- `.env`, `*.pem`, `*.key`, `secrets.*` 파일은 절대 커밋하지 않는다
- push/commit 전 반드시 민감파일 staged 여부를 확인한다
- 토큰/시크릿을 커밋 메시지나 코드에 하드코딩하지 않는다

---

## 🧠 맥락 추론 규칙 (모든 커맨드 공통)

owner / repo / branch 등 필수 정보가 명시되지 않은 경우:
1. $ARGUMENTS에서 직접 추출
2. 이번 대화의 이전 메시지에서 언급된 값 참조
3. 로컬 git 상태 또는 MCP로 원격 상태 조회
4. 위 모두 불명확할 때만 사용자에게 질문

불필요한 질문을 최소화하고, 맥락을 우선 활용한다.

---

## 🛠 코딩 원칙

- 가정하지 않는다. 요청이 모호하면 해석을 나열하고 묻는다.
- 요청을 해결하는 최소 코드만 쓴다. 요청 안 한 기능·추상화·설정·불가능한 케이스의 예외 처리는 넣지 않는다.
- 필요한 줄만 바꾼다. 주변 코드·포맷은 건드리지 않고 기존 스타일을 따른다. 내 변경이 만든 미사용 코드만 지우고, 기존 dead code는 언급만 한다.
- 작업을 검증 가능한 성공 기준으로 바꾼다 (버그 → 재현 테스트 먼저, 다단계 → "단계 → 확인 방법").
- "완료/통과/고쳤다"는 이번 턴에 실행한 명령의 출력과 exit code를 근거로만 말한다. "아마", "될 것" 같은 표현을 쓰지 않는다. (상세: verification-before-completion 스킬)

## 🔤 커밋 메시지 규칙

Conventional Commits 형식을 따른다:
- `feat:` 새 기능
- `fix:` 버그 수정
- `docs:` 문서
- `refactor:` 리팩토링
- `chore:` 기타 유지보수
