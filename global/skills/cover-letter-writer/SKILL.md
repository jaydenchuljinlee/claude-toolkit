# 개발자 자기소개서 작성 스킬

채용 공고, 이력서/경력기술서를 분석하고 기업의 최신 동향을 리서치하여
사람이 직접 쓴 것 같은 자연스러운 개발자 자기소개서를 생성하는 스킬이다.

4개의 서브에이전트를 활용하여 정보 수집을 병렬화하고,
메인 컨텍스트에서 초안 작성과 피드백 반영을 수행한다.

## 서브에이전트 구성

| 에이전트 | 역할 | 실행 시점 |
|----------|------|-----------|
| `cl-job-analyzer` | 채용공고 파싱 → 구조화된 분석 | Phase 1 (병렬 A) |
| `cl-profile-loader` | Notion 이력서/포트폴리오/기존 자소서 스타일 로드 | Phase 1 (병렬 A) |
| `cl-researcher` | 기업 리서치 + 합격 자소서 패턴 분석 | Phase 1 (병렬 B) |
| `cl-notion-publisher` | Notion 페이지 생성/수정 | Phase 3 |

## 오케스트레이션 파이프라인

### Phase 1: 정보 수집 (서브에이전트 병렬 실행)

**그룹 A (즉시 병렬 실행)**:
1. `cl-job-analyzer` — $ARGUMENTS의 채용공고 URL을 전달
2. `cl-profile-loader` — 인자 없음 (Notion 고정 경로)

**그룹 B (그룹 A 완료 후)**:
3. `cl-researcher` — cl-job-analyzer에서 추출한 기업명과 포지션명을 전달

> 예외: 사용자가 기업명을 직접 알려준 경우, 3개 에이전트를 모두 즉시 병렬 실행한다.

각 에이전트의 반환 결과를 확인하고, 누락된 정보가 있으면 사용자에게 요청한다.
특히 자소서 항목(질문+글자수)이 채용공고에 없는 경우, 사용자에게 확인한다.

### Phase 2: 매핑 + 초안 작성 (메인에서 직접 수행)

이 단계는 서브에이전트에 위임하지 않고 메인 컨텍스트에서 직접 수행한다.
스타일 피드백 반영이 핵심이므로 컨텍스트 분리가 적합하지 않다.

**Step 1. 채용공고 ↔ 경력 매핑**

cl-job-analyzer의 필수/우대 역량과 cl-profile-loader의 이력서/포트폴리오를 교차 매핑한다:
- 필수 역량에 대응하는 프로젝트/성과를 찾는다
- 우대사항에 해당하는 경험이 있으면 별도로 표시한다
- 매칭되지 않는 요구사항은 유사 경험이나 학습 의지로 보완 가능한지 확인한다
- 이 매핑 결과는 내부적으로만 활용하며, 사용자에게 별도로 보여줄 필요는 없다

**Step 2. 초안 작성**

아래 우선순위로 스타일을 적용한다:
1. **최우선**: cl-profile-loader가 반환한 "기존 자소서 스타일 분석" 결과
2. **보조**: 이 파일의 스타일 가이드 (아래 참조)
3. **참고**: cl-researcher가 반환한 "합격 자소서 패턴"

> 기존 자소서 스타일과 이 파일의 스타일가이드가 충돌하면, 기존 자소서의 패턴을 따른다.
> 실제로 사용자가 작성/승인한 스타일이 가장 신뢰할 수 있는 기준이다.

각 항목 작성 시:
- cl-researcher의 기업 동향을 본문에 자연스럽게 녹여낸다 (나열 금지)
- 매핑 결과에서 가장 강한 연결 고리를 중심으로 서술한다
- SCAR(Situation-Crisis-Action-Result) 구조로 경험을 풀어낸다

**Step 3. 글자 수 검증**

작성 후 반드시 bash로 글자 수를 검증한다:
```bash
printf '%s' '(자소서 본문)' | wc -m
```
글자 수 제한이 있는 경우 95~100% 범위로 조정한다.

### Phase 3: Notion 저장

1. 초안을 사용자에게 제시하고 확인을 받는다
2. 사용자가 승인하면 `cl-notion-publisher` 호출
3. 전달 내용: 기업명, 포지션명, 도메인/팀명, 마감일, 자소서 본문, 셀프리뷰
4. 셀프리뷰 내용은 Phase 2에서 자동 생성:
   - 이력서 연결 고리: 매핑 결과에서 추출
   - 기업 리서치 활용: cl-researcher 결과에서 추출
   - 면접 예상 질문: 자소서 내용 기반으로 생성
5. 생성된 Notion 페이지 URL을 사용자에게 반환한다

### Phase 4: 피드백 루프

사용자가 피드백을 주면:
1. 메인에서 직접 수정 (기존 자소서 스타일 + 스타일가이드 재적용)
2. 글자 수 재검증
3. `cl-notion-publisher`를 수정 모드로 재호출 (기존 page_id 전달)
4. 수정된 Notion 페이지 URL 반환

## 스타일 가이드

자기소개서의 품질을 결정하는 핵심 규칙이다. 모든 항목 작성 시 반드시 따른다.
단, cl-profile-loader의 "기존 자소서 스타일 분석"이 이 가이드보다 우선한다.

### 톤 & 어조: 사람이 쓴 것처럼

자소서는 **AI가 아니라 지원자 본인이 쓴 글**처럼 읽혀야 한다.

- **자연스러운 흐름**: "~했습니다", "~한 적이 있습니다", "~인 것 같습니다" 등 
  실제 사람이 쓰는 어미를 사용한다. **"확신합니다", "매료되었습니다" 같은 
  과도하게 격식적인 표현은 피한다.**
- **경험을 이야기하듯 풀어낸다**: "이전 회사에서 ~ 할 때", "~를 만난 적이 있는데" 같이
  대화체에 가까운 서술을 섞는다. **모든 문장이 같은 톤이면 기계적으로 느껴진다.**
- **본인 업무 경험에서 출발한다**: 기업에 대한 관심은 본인이 해당 업무를 경험하면서
  자연스럽게 느낀 방향성에서 시작한다. **외부 기사나 뉴스에서 관심이 시작된 것처럼
  쓰지 않는다.**
- **어미는 격식체를 유지한다**: "~했습니다", "~있습니다", "~생각합니다" 등
  일관된 격식체를 사용한다. **"~했고요", "~니까요", "~거든요" 같은
  구어체 종결어미는 사용하지 않는다.**

### 금지 표현

다음 표현은 AI가 작성한 느낌을 주므로 사용하지 않는다:

- "확신합니다", "자부합니다", "매료되었습니다"
- "~에 부합합니다", "~와 일맥상통합니다"
- "핵심적인 역할을 수행하며", "차별화된 가치를 제공하겠습니다"
- "깊은 전문성을 바탕으로", "탁월한 역량을 갖추고 있습니다"
- 같은 구조의 문장을 3회 이상 반복 (예: "첫째, ~입니다. 둘째, ~입니다. 셋째, ~입니다.")
- "~기사를 접하며", "~소식을 접하고", "~뉴스를 보면서" 등 외부 계기 표현
- "~했고요", "~니까요", "~거든요" 등 구어체 종결어미

### 숫자와 성과 표현

숫자는 임팩트를 줄 수 있지만, 나열하면 보고서처럼 읽힌다.

- 한 문단에 구체적 수치는 최대 2개까지만 사용한다
- 나머지 성과는 "대규모 데이터를 다뤄본 경험", "쿼리 성능을 크게 개선한 경험" 같이
  정성적으로 표현한다
- 가장 인상적인 수치 1~2개만 골라서 사용하고, 나머지는 맥락으로 전달한다

### 구조

- **첫 문장에서 핵심 메시지를 전달한다.** 두괄식이 기본이다.
- 단락 전환이 자연스러워야 한다. **"또한", "더불어" 같은 접속사를 반복하지 않는다.**
- 마지막 문단은 입사 후 포부나 다짐으로 마무리하되, 
  **"최선을 다하겠습니다" 수준의 상투적 표현보다는 구체적인 목표**를 언급한다.

### 굵은 표시(Bold) 활용

자소서 본문에서 **읽기 쉽도록 핵심 키워드와 중요 문구에 굵은 표시**를 한다.

- **기술 스택/도구명**: Spring Boot, Kotlin Coroutine, Kubernetes 등 핵심 기술명
- **정량 성과**: "**500만 MAU**", "**2억 건 규모**", "**수수료율 0.1% 절감**" 등 수치
- **직무/역할**: "**AI 채팅 서버를 구축**", "**결제 시스템을 담당**" 등 핵심 업무
- **기업/서비스명**: "**H-Chat**", "**프라이빗 LLM**" 등 지원 기업의 서비스
- 과용하지 않는다. 한 문단에 굵은 표시는 **2~3개**가 적절하다.
  모든 문장에 굵은 표시가 있으면 오히려 강조 효과가 사라진다.

### 항목별 작성 포인트

**지원동기 유형**:
- **본인의 업무 경험에서 출발**하여 자연스럽게 해당 기업/포지션에 관심을 갖게 된 흐름으로 시작한다
- 기업의 방향성과 **본인의 경험/가치관이 연결되는 지점**을 보여준다
- 입사 후 하고 싶은 일을 **구체적으로** 언급한다

**직무적합성 유형**:
- 채용 공고의 필수/우대 역량에 대응하는 **업무 경험과 기술 스킬**을 서술하는 공간이다
- **핵심 질문: "왜 내가 이 직무에 적합한가?"**에 답한다
- 수행한 업무와 보유 기술이 이 포지션의 요구사항과 **어떻게 연결되는지**를 보여준다
- **문제 상황, 해결 과정, 트러블슈팅 사례는 절대 포함하지 않는다**
  (문제 해결은 포트폴리오나 면접에서 다룰 영역이다)
- **서술 구조: [업무/역할] → [사용 기술] → [정량 결과]** 흐름으로 서술한다
  - 예시: "Spring Boot 기반 AI 채팅 서버를 구축하고(업무), 
    Kotlin Coroutine을 활용한 비동기 배치 처리 구조를 설계하여(기술), 
    500건 규모의 동시 갱신을 안정적으로 처리한 경험이 있습니다(결과)"
- **정량 성과를 적극 활용**한다: 수치가 있는 성과는 경험의 규모와 임팩트를 보여주는 
  가장 효과적인 근거이다. **"2억 건 규모", "500만 MAU", "수수료율 0.1% 절감"** 등 
  업무의 규모를 드러내는 수치를 경험 설명에 자연스럽게 포함한다
- **첫 문장에서 포지셔닝**한다: 직무적합성의 첫 문장은 **자신의 핵심 역량을 
  한 문장으로 요약**하는 포지셔닝 문장으로 시작한다
- **기술 키워드는 업무 맥락 안에서**: 기술명을 단독으로 나열하지 않고, 
  **어떤 업무에서 어떤 목적으로 사용했는지** 맥락과 함께 서술한다
- 예시 (나쁜 예): "Hikari Pool이 고갈되는 문제를 발견했고, 
  트랜잭션을 분리하여 해결했습니다" → **문제 해결 서술이므로 부적합**

**입사 후 포부 유형**:
- "무엇을 배우겠다"가 아니라, **기존 경험을 어떻게 활용하여 기여할 것인가**를 서술한다
- 입사하면 내가 뭘 얻는가(학습/성장)가 아니라, 
  **내가 가진 역량으로 팀/서비스에 어떤 가치를 더할 수 있는가**에 초점을 맞춘다
- 예시 (나쁜 예): "RAG 파이프라인을 익히고 싶습니다" → **학습 중심이므로 부적합**
- 예시 (좋은 예): "결제 시스템에서 검증한 처리량 제어 패턴을 AI 서비스의 
  안정적 확장에 적용하겠습니다" → **기여 중심**
- 해당 기업/팀에서만 가능한 **구체적인 기여 포인트**를 언급한다
- **단기(즉시 기여)와 중장기(경험 축적 후 기여)를 구분**하면 좋다

## 글자 수 규칙

자소서의 글자 수는 **공백을 포함한 글자 수(잡코리아 기준)**로 계산한다.

- 한글 1자 = 1자, 영문 1자 = 1자, 공백 1칸 = 1자, 줄바꿈 = 1자
- 쉼표, 마침표 등 특수문자도 각각 1자로 계산한다

지정된 글자 수의 95~100% 범위를 목표로 작성한다.
예를 들어 1000자 제한이면 950~1000자 사이로 맞춘다.

작성 후 반드시 다음 방법으로 글자 수를 검증한다:

```bash
printf '%s' '(본문 내용)' | wc -m
```

글자 수가 범위를 벗어나면 자동으로 조정한 뒤 결과를 사용자에게 알린다.

## 참고: 좋은 개발자 자소서의 원칙 (코드잇 스프린트 가이드 기반)

- 내가 하고 싶은 말이 아니라, 채용 담당자가 듣고 싶은 말을 쓴다
- 열정이나 열심을 단어로 강조하지 않고, 구체적인 경험과 결과로 보여준다
- "why"를 5번 반복하며 깊이를 더한다 (drill-down)
- 기업 정보를 탐색하고, 본인의 경험과의 연결 고리를 만든다
  (회사 홈페이지, 최근 3개월 뉴스, 기술 블로그, 채용 페이지 등 활용)
- 스토리텔링: 상황(Situation) → 위기(Crisis) → 행동(Action) → 결과(Result)
